ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Этап: Baseline-прогноз спроса (помесячный)

Контекст:
В рамках проекта автоматизации заказов для магазина конфет
выполнен сбор помесячных продаж (январь–ноябрь) и XYZ-анализ ассортимента.
Для товаров классов X и Y (xyz_operational) разрешено прогнозирование спроса.
Перед применением ML-моделей необходимо реализовать baseline-прогноз
как точку отсчёта и эталон качества.

Цель этапа:
1. Реализовать простые и интерпретируемые прогнозы спроса
2. Оценить прогнозируемость данных
3. Получить эталон для сравнения с ML-моделями
4. Подготовить основу для расчёта заказов

Входные данные:
Продажи (sales_df):
- sku        — артикул товара
- month      — месяц продажи (YYYY-MM)
- qty        — количество продаж за месяц

XYZ-классификация:
- sku
- xyz_operational

К прогнозированию допускаются только товары:
xyz_operational ∈ {X, Y}

Выходные артефакты:
1. Ноутбук:
   notebooks/03_baseline_forecast.ipynb

2. DataFrame с прогнозами:
   - sku
   - forecast_qty
   - baseline_type

3. Таблица качества прогноза:
   - sku
   - mae
   - mape

Ограничения:
Запрещено:
- использовать ML-модели
- использовать Prophet, ARIMA, нейросети
- прогнозировать товары классов Z и Unknown

Разрешено:
- средние значения
- последние значения
- простые агрегаты pandas

Этапы выполнения:

1. Отбор товаров для прогноза
   - Отфильтровать продажи только по SKU классов X и Y
   - Сформировать датасет sales_xy

2. Подготовка временных рядов
   - Агрегировать данные до формата:
     sku | month | qty
   - Проверить количество месяцев истории на SKU
   - Исключить SKU с историей менее 3 месяцев

3. Реализация baseline-моделей

   Baseline 1 — Last Month
   Логика:
   прогноз = продажи за последний доступный месяц

   Baseline 2 — Moving Average
   Логика:
   прогноз = среднее значение за последние N месяцев
   Требуется реализовать:
   - N = 3
   - N = 6 (если достаточно истории)

4. Валидация прогноза
   - Обучение: январь – октябрь
   - Тест: ноябрь
   - Сравнить прогноз с фактическими продажами ноября

5. Метрики качества
   Обязательные метрики:
   - MAE — средняя абсолютная ошибка
   - MAPE — средняя абсолютная процентная ошибка

   Рассчитать:
   - по каждому SKU
   - агрегированные значения (среднее, медиана)

Анализ результатов:
В ноутбуке необходимо зафиксировать выводы:
- какая baseline-модель лучше для X товаров
- какая baseline-модель лучше для Y товаров
- есть ли товары с систематическим пере- или недопрогнозом
- можно ли улучшить качество прогноза без ML

Критерии завершения этапа:
Этап считается завершённым, если:
- реализованы минимум 2 baseline-модели
- рассчитаны MAE и MAPE
- определены товары, пригодные для прогнозирования
- зафиксированы ограничения и выводы

order_qty = forecast_qty − stock_qty + safety_stock

Примечание:
Baseline-прогноз является обязательной частью production-системы
и используется как fallback даже при наличии ML-моделей.
