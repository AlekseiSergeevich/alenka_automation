ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Этап: Расчёт safety stock и заказов (order_qty)

Контекст:
В проекте автоматизации заказов для магазина конфет выполнены:
- сбор помесячных продаж
- XYZ-анализ ассортимента (xyz_operational)
- baseline-прогноз спроса для X и Y товаров

На данном этапе необходимо реализовать:
1) расчёт страхового запаса (safety stock) на основе стандартного отклонения
2) расчёт рекомендуемого объёма заказа

---

Цель этапа:
1. Преобразовать прогноз спроса в управленческое решение
2. Учесть нестабильность спроса через XYZ-классификацию
3. Получить финальную рекомендацию по заказу для каждого товара

---

Входные данные:

1. Прогноз спроса (baseline_forecast):
- sku               — артикул товара
- forecast_qty      — прогноз спроса на следующий месяц
- baseline_type     — тип baseline-модели

2. Продажи (monthly_sales):
- sku
- month
- qty

3. XYZ-классификация (xyz_operational):
- sku
- xyz_operational ∈ {X, Y, Z, Unknown}

4. Остатки на складе (stock_df):
- sku
- stock_qty         — текущий остаток

---

Ограничения и правила:

1. Safety stock рассчитывается ТОЛЬКО для товаров:
   xyz_operational ∈ {X, Y}

2. Для товаров классов Z и Unknown:
   - прогноз не используется
   - заказ не рассчитывается автоматически
   - требуется ручное решение

3. Если рассчитанный order_qty < 0:
   - order_qty = 0

---

Логика расчёта safety stock:

1. Для каждого SKU рассчитывается стандартное отклонение продаж:

   std_qty = std(qty) по помесячным данным

2. Коэффициенты safety stock задаются по XYZ-классу:

   xyz_operational == X:
       k = 0.5

   xyz_operational == Y:
       k = 1.0

3. Формула расчёта:

   safety_stock = k * std_qty

4. Safety stock:
   - округляется до допустимого уровня (целое / десятые)
   - не может быть отрицательным

---

Логика расчёта заказа:

Для товаров X и Y:

1. Базовая формула:

   order_qty = forecast_qty − stock_qty + safety_stock

2. Применение ограничений:
   - если order_qty < 0 → order_qty = 0

3. Финальный результат должен отражать:
   - реальную потребность в заказе
   - страховой запас на случай ошибки прогноза

---

Выходные данные:

Итоговая таблица рекомендаций:

- sku
- xyz_operational
- forecast_qty
- stock_qty
- std_qty
- safety_stock
- order_qty

Анализ и выводы (обязательно):

В ноутбуке должны быть зафиксированы выводы:
1. Как safety stock влияет на итоговый заказ
2. Для каких товаров order_qty = 0 и почему
3. Отличие логики для X и Y товаров
4. Ограничения подхода (помесячные данные, отсутствие lead time)

---

Критерии завершения этапа:

Этап считается завершённым, если:
- рассчитан safety stock на основе стандартного отклонения
- реализована логика заказа
- получена финальная таблица рекомендаций
- логика объяснима и воспроизводима
